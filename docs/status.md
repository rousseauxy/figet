# Verified behaviour

This file records what was checked, how it was checked, and when. It is evidence, not a changelog: a row
appears only where the source material names a client, a command, a request or a measured number. It was
distilled from a dated build diary covering 2026-09-11 to 2026-09-16, which is kept privately.

Where a row says "falsified", the change was reverted or disabled and the test was seen to fail before
being restored. "The reference server" and "the reference client" mean the commercial package server this
project replaces and its command-line client.

## Known gaps

The diary is explicit that the following were **not** verified. They are listed here so that no row above is
read as covering them.

- **No end-to-end automation run.** The registration-URL fix was reasoned from the source of the Ansible
  module that compares `SourceLocation` as a string; the baseline that consumes it was never run end to end.
- **Chocolatey is not part of the client matrix.** Chocolatey 2.7.4 was exercised once against a local
  instance; it has no recording, no fixture set and no replay test.
- **No real mounted network share inside a container.** Folder-backed asset directories were checked against
  folders created on the test host, and a UNC storage root was checked from a workstation. Neither is an SMB
  mount presented to a pod.
- **API access tokens have never been checked against a real issuer.** Every token test runs against an
  in-process provider that signs with its own published key; no token from a real identity provider or CI
  system has been tried.
- **The token half of request-log attribution is unverified.** The signed-in path was shown live; tokens are
  stored hashed and none was minted to test with.
- **The client-side theme choice fix was never seen in a browser.** The diagnosis rests on reading the
  delivered HTML, the stylesheet and the script, not on observation. It is stated as falsifiable.
- **The styled select's open popup was not exercised.** Only the computed `appearance` value and the closed
  control were checked headlessly; opening the list needs a real click.
- **The replacement pager's click wiring was never reached.** It is behind a "more than one page" condition
  and no feed used for testing holds more than fifty packages.
- **Parts of the upload drop zone are still unclicked.** The page capture had its scripts removed, so drag,
  progress and confirm-before-replace were not exercised in a browser; a drop during a large upload,
  answering the row's question both ways, ticking the replace switch for a dropped file, and importing an
  archive with a failing entry are all still to be driven by hand.
- **The write side of the reference server's asset contract was never recorded.** Writing to that instance
  was not possible; the write rules come from the reference client's models and the published documentation.
- **`Update-Module` across a page boundary was never recorded or replayed.**
- **Whether a 405 would also stop the client adopting the `/api/v2` alias was not tested.** The fix matches
  the reference server's 404 rather than testing the alternative.
- **Where inside the server the tag-heavy page time is spent was not measured.** An attempt to read it from
  the request log was discarded as unreliable.
- **No controlled A/B of the one-walk change.** The before figure is a single sample.
- **Two tests are known to be intermittent.** One counts background refreshes and allows at most two, and a
  loaded machine can produce a third; one share-folder test failed in a single full run and passed alone and
  in the two full runs after, and has not been investigated.
- **The un-cache endpoint and its admin panel have no test.** The browser harness and the upstream stub live
  in different fixtures, so the case needs an admin session on a proxy feed and cannot be assembled.
- **Autocomplete `totalHits` is `skip + returned count`, not the full count.** No client is known to rely on
  it, but that has not been checked against one.
- **The image is not built on the development machine.** CI and a Linux host build it; there is no Docker on
  the workstation the code is written on.
- **The compatibility scripts run by hand.** They are not in CI, which needs a Windows runner.
